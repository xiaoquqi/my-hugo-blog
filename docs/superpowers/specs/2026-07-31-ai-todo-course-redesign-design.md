# AI Todo 课程重构设计：从技术栈递进到 AI Native 产品开发

## 背景与目标

`content/training/ai-todo/` 现有课程（Part 3-11，对应文件 `02-first-todo-page.md` 至
`10-review-and-extension.md`，共 9 个文件、65 个编号小节、约 4000 行）本质上是一条
**技术栈递进主线**：静态页面 → Vue → Flask → SQLite → AI 功能 → AI 协作方法论 →
工程化升级（Pydantic/FastAPI） → Docker 部署 → 复盘扩展。每接触一个新技术就单独起一节
"XX 是什么"（如"16. Vue 是什么""25. Flask 是什么""52. Pydantic 是什么""53. FastAPI
是什么""56. Docker 是什么"）。

这与课程真正的目标背道而驰。课程目标不是：

> 借助 AI 学会 Vue、FastAPI、数据库和代码结构。

而是：

> 完全不要求理解代码内部，让零基础用户通过 AI 完成需求定义、产品生成、调试、验收和上线。

因此需要把 Part 3 起的全部内容推翻重写，围绕"需求 → 开发 → 测试 → 验收"这套方法论，
而不是技术名词，组织课程。

Part 1（`00-introduction/`）和 Part 2（`01-environment.md`）已经在本次重构之前完成了
方向一致的调整（AI Native 命名心智模型、人机分工、环境安装 + 工具选型 + cc-switch 配置），
不在本次范围内，维持现状。

## 可借鉴与不可直接教的边界

沿用用户给出的判断，作为后续写正文时的取舍依据：

| 来源 | 借鉴内容 | 是否直接教给学生 |
| --- | --- | --- |
| TodoMVC | 功能规格和验收标准清单（新增/完成/编辑/删除/筛选/剩余数量/持久化） | 是——作为产品验收清单 |
| 产品经理入门方法论 | 需求、用户故事、功能边界 | 是 |
| 软件测试方法论 | 测试场景设计、异常情况、验收流程 | 是 |
| Prompt Engineering | 清晰指令、分阶段执行、上下文管理 | 是 |
| GitHub 基础操作 | 版本、提交、推送、回滚 | 只学操作，不讲原理 |
| 部署平台/云主机 | 上线流程、日志、环境变量、域名与 HTTPS | 只学操作，不讲原理 |
| MDN、Vue、FastAPI 官方文档 | 技术正确性参考 | 否——学生不需要学习，仅供课程设计者核对细节 |
| Full Stack Open | 项目递进顺序 | 否——仅供课程设计者参考结构 |

| Part | 文件 | 内容 | 对应旧内容 |

| 7 | `06-ai-features.md` | 加入智能功能（AI 拆任务/总结/分类/判优先级）：从"普通 Todo"升级成"AI Todo"的转折点 | 旧 06（加入 AI 能力），整体保留但顺序后移 |

### 关键决定

1. **Flask 彻底不出现。** 后端一路用 FastAPI，不存在"从 Flask 升级到 FastAPI"这一步——
   反正都是提示词让 AI 写，没有理由先教一个要被替换掉的技术。
2. **技术名词集中在 Part 3 讲一次**，之后的课程正文里不再单独起"XX 是什么"小节；
   需要提到某个技术时，作为已经建立好的认知自然带过。
3. **AI 产品功能（任务拆解/总结/分类/优先级）保留，但后移。** 产品前期是一个普通、可用的
   Todo；把它变成会思考的"AI Todo"是后期的一次专门升级（Part 7），呼应"你不需要一开始
   就搞复杂，先把基础做扎实"的方法论。
4. **"需求 → 开发 → 测试 → 验收"方法论只在 Part 4（核心功能）完整讲一次**，后续
   Part 5-8 复用同一套方法论、不重复讲解，只应用到各自的功能领域。
5. **旧"工程化升级"整章（Pydantic 原理、组件化设计原则等）不再作为独立内容**——
   这些 AI 会自动处理好，不占学生主线时间；其中"认识技术栈"部分并入 Part 3。
6. **容器基础和 GitHub 上线拆成两课**，分别对应"部署前要知道什么"和"完整上线操作流程"。

## 遗留联动项

Part 1 第 3 篇（`00-introduction/03-what-we-build.md`）里的技术路线图，目前写的是：

```text
静态 Todo 页面 → Vue Todo 应用 → Flask Todo API → SQLite 保存 Todo →
AI 帮你拆解任务 → AI 总结/分类/判断优先级 → 工程化升级（FastAPI 等） →
Docker 部署上云 → 扩展成内容生成器/知识库/小程序
```

需要在本次 Part 3-10 内容写完后，同步改成与新顺序一致的路线图（去掉 Flask 和"工程化升级"
独立步骤，插入"架构基础""登录多用户""容器基础""GitHub 上线"）。在开始写第一课正文
之前先不动它，避免中途表述反复横跳；等新课程结构稳定后一次性同步。

## 实施方式

本次 spec 只锁定大纲和取舍，不在同一轮写完全部正文——9 个文件、每篇预计 300-500 行，
量级和之前 Part 1/2 的调整不是一个数量级。后续按 Part 3 → Part 10 顺序，一课一课地写、
一课一课地过 hugo 本地预览确认，再推送。
